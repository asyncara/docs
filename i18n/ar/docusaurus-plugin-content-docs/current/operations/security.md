title: "الأمان وحدود الثقة"
---

Asyncara تجريبي وليس إطار حماية تطبيقات. عدم حجب I/O لا يجعل المدخلات موثوقة.

## الشبكة والمدخلات

لا تسمح للطلب باختيار URL أو proxy أو CA أو مسار محلي تعسفياً. تحقّق من الوجهة والمنفذ وإعادة التوجيه ضد SSRF، وانتبه لتغير DNS. أبق تحقق TLS مفعلاً وحدد نطاق استعمال شهادات العميل.

تحقّق من بنية JSON وحجمه ومعاملات المسار والاستعلام. Origin ليس مصادقة. المصادقة والصلاحيات وCORS وCSRF وrate limits مسؤولية التطبيق. اربط على loopback خلف proxy موثوق إن لم تكن تريد تعرضاً مباشراً.

## الملفات والأسرار

استخدم مجلدات خاصة موثوقة للرفع والتتبّع. فحص المسار ليس حماية كاملة ضد تبديل symlink متزامن. لا تركّب shell أو SQL أو مسارات bootstrap من إدخال غير موثوق؛ اربط المعاملات وثبّت سجل وظائف ProcessPool.

لا تنشر credentials أو SQL values أو Authorization أو traces كاملة للعميل. metadata التشغيل قد تكون حساسة حتى دون payload. الإنهاء القسري قد يترك ملفاً جزئياً أو نتيجة كتابة بعيدة مجهولة؛ استخدم idempotency والنشر الذري.

حدود ledger ليست لكل مكتبة أو kernel أو طفل. حدّث PHP والاعتماديات، وطابق ABI وNTS/ZTS. SHA256 يتحقق من سلامة الملف لكنه ليس توقيع ناشر مستقلاً. راجع [الترخيص](license.md)، وبلّغ الثغرات عبر وسيلة أمنية خاصة متاحة للمنظمة دون نشر أسرار في issue عام.
