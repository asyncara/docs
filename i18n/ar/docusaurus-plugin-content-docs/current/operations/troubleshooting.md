title: "حل المشكلات حسب العَرَض"
---

اجمع php -v وphp --ini وasyncara --check وRuntime::information أولاً. قد يستخدم launcher مفسراً مختلفاً عن shell أو خادم الويب.

| العَرَض | ما يجب فحصه |
|---|---|
| تعذر تحميل الامتداد | ABI والمعمارية وNTS/ZTS والمكتبات؛ لا تعِد تسمية binary غير مطابق |
| Class not found | autoloader مع الامتداد؛ استخدم launcher أو Composer |
| لا توجد حزمة | مصفوفة الأصول المنشورة، لا تفترض build تلقائياً |
| فشل TLS | CA وSAN والساعة والسلسلة؛ لا تعطّل التحقق |
| توقف timers | CPU أو PHP حاجب أو logging متزامن |
| انتظار دائري بالمعاملة | طفل ينتظر اتصالاً يملكه الأب المنتظر له |
| امتلاء pool | استعارة متسربة أو معاملة طويلة |
| ملف جزئي | download/write مباشر فشل؛ اختر atomic عند الحاجة |

## عزل المشكلة

استخدم endpoint محلياً وبنفس PHP/backend، واحفظ الإدخال الفاشل. التتبّع في تشغيل منفصل؛ لا تغيّر عدد ticks لتنجح الحالة. بقاء العملية حية ليس تقدماً، ولقطة RSS ليست إثبات خلو من التسرب.

عند طلب المساعدة أرفق سكربتاً صغيراً كاملاً ونسخة الحزمة وOS/architecture وPHP/backend والنتيجة الفعلية. اذكر TLS/proxy والتتبّع، واحذف الأسرار. لا تنشر بيئة الإنتاج أو أرشيفاً خاصاً كاملاً في issue عام.
