---
title: "ما هي Asyncara؟"
---

Asyncara امتداد أصلي ومكتبة PHP لبناء تطبيقات تنتظر الشبكة والملفات وقواعد البيانات دون تعطيل بقية المهام. تكتب استدعاءات واضحة، وتعلّق الـFiber الحالية عند الانتظار، ثم تستأنفها حلقة الأحداث عندما تصبح النتيجة متاحة. هذه الوثائق موجّهة إلى **المطوّر الذي يستخدم المكتبة**: كل دليل يشرح الإعداد والنتيجة وملكية الموارد ومعالجة الفشل، ثم يربط ذلك بمرجع الواجهة.

الواجهات الأصلية للمكتبة هي نقطة البداية: `HttpClient` للطلبات، `Files` للملفات، واتصالات قاعدة البيانات الخاصة بـAsyncara. لا تحتاج إلى تفعيل Hooks، ولا يصبح `curl_exec()` أو PDO أو `file_get_contents()` غير حاجب بمجرد تحميل الامتداد.

## اختر نقطة البداية

إذا لم تثبّت Asyncara، ابدأ بـ[التثبيت](installation.md)، ثم [أول تطبيق](quickstart.md). لبناء خدمة ويب انتقل إلى [Native Server](server/routing.md). لجلب عدة خدمات من تطبيق قائم اقرأ [عميل HTTP](http/client.md) و[تجميع الخدمات](recipes/aggregation.md). لمعالجة دفعات بيانات اقرأ [الطوابير](runtime/synchronization.md) و[مسار معالجة محدود](recipes/pipeline.md).

## التزامن ليس دائماً توازياً

PHP داخل العملية الواحدة يعمل تعاونياً: مهمة PHP واحدة تنفّذ في اللحظة نفسها، والمهام الأخرى تتقدم عندما تعلّق المهمة الحالية. الانتظار الشبكي غير الحاجب مناسب لآلاف العمليات المتداخلة، لكن حلقة حساب طويلة لا تصبح أسرع تلقائياً. استخدم [ProcessPool](io/processes.md) للحسابات المستقلة في عمليات منفصلة.

| القدرة | طريقة التنفيذ الفعلية |
|---|---|
| TCP وUDP وRedis | مقابس غير حاجبة وجاهزية epoll أو poll |
| HTTP الافتراضي | تكامل libcurl multi مع حلقة الأحداث |
| HTTP الاختياري Hyper | Rust/Hyper وrustls، تقوده حلقة Asyncara؛ ليس Tokio thread pool |
| PostgreSQL | libpq غير حاجب |
| MySQL/MariaDB | آلة حالات Connector/C start/continue |
| SQLite والملفات وDNS | عمال أصليون محدودون خارج خيط حلقة الأحداث |
| ProcessPool | مفسرات PHP مستقلة في عمليات نظام منفصلة |

واجهة Native Asyncara لا تعني أن كل تنفيذ هو I/O غير حاجب على مستوى النواة. الملفات المنتظمة تستخدم عمال pthread؛ `io_uring` ليس backend متاحاً.

## نطاق هذا الدليل

الواجهة المرجعية هي 0.10.0، مع تمييز حزم Android التجريبية اللاحقة صراحة. حالة المشروع **EXPERIMENTAL**. وجود اختبار ناجح لمسار معين لا يساوي اعتماد كل خادم أو Proxy أو إصدار نظام. صفحة [التوافق](operations/compatibility.md) تفصل الدعم المتاح عن المؤجل. لا يتضمن الدليل وعود أداء مطلقة أو ادعاء جاهزية إنتاج شاملة.

تستخدم الأمثلة أسماء الفئات كما توجد في المصدر، وبالأخص `Asyncara\HTTP\HttpClient` لعميل HTTP و`Asyncara\Server\Response` لاستجابة الخادم. لا تخلط بين الاستجابتين، ولا تغيّر حالة مجلد `HTTP` في مشاريع PSR-4 على Linux.
