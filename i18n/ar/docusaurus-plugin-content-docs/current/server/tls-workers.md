---
title: "TLS وتعدد العمال"
---

الخادم الافتراضي مفسر واحد. TLS يحمي النقل، وتعدد العمال يضيف عمليات مستقلة، لكن أياً منهما لا يجعل globals مشتركة وآمنة.

```php
$app->listen('0.0.0.0:8443', ['tls' => [
    'certificate' => '/etc/asyncara/server-chain.pem',
    'privateKey' => '/etc/asyncara/server-key.pem',
]]);
```

تُقرأ ملفات PEM المحلية عند البدء قبل قبول الطلبات. احمِ صلاحيات المفتاح واستعمل شهادة تطابق الاسم الذي يتحقق منه العميل. أضف `clientCa` لطلب شهادة عميل موثوقة. تغيير الملفات يحتاج دورة listener/worker جديدة؛ لا يوجد ضمان hot reload تلقائي. TLS لا يضيف خادم HTTP/2 أو HTTP/3.

## عمليات متعددة

```php
$app->listen('127.0.0.1:8080', ['workers' => 4]);
```

يتطلب ذلك CLI وpcntl وposix ودورة prefork المدعومة على Linux. استخدم منفذاً ثابتاً؛ :0 غير مقبول لعدة عمال. ابدأ المشرف قبل فتح محرك أصلي أو اتصالات أو خيوط. افتح اتصالات قاعدة البيانات كسولاً داخل كل طفل، لا في الأب قبل fork.

لكل عامل حالته وحدوده وpool الخاص به. أربعة عمال بسعة8 لكل pool قد يفتحون32 اتصالاً. Queue داخل الذاكرة ليست مشتركة بين العمليات. عند فشل عامل يغلق المشرف المجموعة بدلاً من إعادة العمل تلقائياً؛ استخدم مدير خدمات خارجي لإعادة تشغيل التطبيق وفق سياسة واضحة.

`onReady` مناسب لإعلان الجاهزية. `stop()` يوقف القبول ويبدأ الإغلاق؛ SIGTERM/SIGINT متاحان عند وجود pcntl. لا تعرض مسار إغلاق غير محمي عبر الشبكة. إذا اضطر المشرف لقتل عامل عالق فلا يمكن ضمان finally أو تنظيف PHP المعتاد.
